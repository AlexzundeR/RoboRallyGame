# RoboRally Project

## Основные правила игры

### Фазы игры

1. **Programming (Программирование)** - игроки выбирают 5 карт для регистров
2. **Activation (Выполнение)** - роботы выполняют регистры по очереди (от наивысшего приоритета)
3. **Cleanup (Очистка)** - конец раунда

### Карты программирования

| Тип | Обозначение | Описание | Кол-во |
|-----|-------------|----------|--------|
| Move 1 | M1 | Перемещение вперёд на 1 клетку | 18 |
| Move 2 | M2 | Перемещение вперёд на 2 клетки | 12 |
| Move 3 | M3 | Перемещение вперёд на 3 клетки | 6 |
| Back Up | ⬇ | Перемещение назад на 1 клетку | 6 |
| Turn Left | ↺ | Поворот налево (90°) | 18 |
| Turn Right | ↻ | Поворот направо (90°) | 18 |
| U-Turn | ⟲ | Разворот на 180° | 6 |

### Типы плиток (Tiles)

| TileType | Обозначение | Описание |
|----------|-------------|----------|
| Floor | · | Обычный пол |
| Wall | █ | Стена - непроходимо |
| Pit | (пусто) | Яма - робот уничтожен |
| Start | S | Стартовая позиция |
| Checkpoint | 1-4 | Контрольная точка (нужно посетить все 4) |
| ConveyorCW/CCW | ↻/↺ | Конвейер (1 клетка/ход) |
| ExpressConveyor | ⤴/⤵ | Экспресс-конвейер (2 клетки/ход) |
| GearCW/CCW | ↺/↻ | Шестерёнка - поворот робота |
| LaserH/LaserV | ━/┃ | Лазер на плитке |

### Приоритет карт

- Карты выполняются в порядке убывания приоритета (чем больше число, тем раньше)
- При одинаковом приоритете - слева направо по карте

### Повреждения

- Стандартный лазер: 1 HP
- Робот уничтожается при 10 HP
- 4 чекпоинта = победа

## Суть игры

### Обзор

RoboRally - это игра-перегонка по лаборатории, где игроки программируют движения своих роботов, чтобы первыми пройти все контрольные точки.

### Игровой раунд

**1. Programming Phase (Программирование)**
- Каждый игрок получает 9 случайных карт
- Игроки выбирают 5 карт для своих регистров (слоты 1-5)
- Карты в регистрах определяют порядок действий робота
- Регистры видны всем игрокам (открытая информация)

**2. Activation Phase (Выполнение)**
- Все роботы выполняют регистр 1 одновременно
- Затем регистр 2, и так далее до 5
- Порядок внутри регистра: от высокого приоритета карты к низкому

**3. Cleanup Phase (Очистка)**
- Проверка чекпоинтов
- Восстановление повреждений (опционально)
- Переход к следующему раунду

### Выбор карт

- Карты имеют приоритет (100, 150, 350 и т.д.)
- Больший приоритет = робот действует раньше
- При одинаковом приоритете - слева направо по игровому полю
- Игроки могут блокировать друг друга

### Как выиграть

1. Посетить все 4 контрольные точки в правильном порядке (1→2→3→4)
2. Вернуться на старт после последнего чекпоинта
- Побеждает первый, кто сделает это

### Дополнительные механики

- **Лазеры** - стреляют в конце каждого регистра
- **Конвейеры** - перемещают роботов после движения
- **Шестерёнки** - поворачивают роботов
- **Ямы** - уничтожают роботов (нужен HoverUnit)
- **Апгрейды** - дают специальные способности

## Система повреждений

### Жизни (LifeTokens)

| Параметр | Значение |
|----------|----------|
| Максимум LifeTokens | 3 |
| Урон от лазера | 1 HP |
| Урон от столкновения | 1 HP |
| Критический урон | 10 HP |

### Статусы робота (RobotStatus)

| Статус | Описание |
|--------|----------|
| Active | Робот активен и управляется игроком |
| PowerDown | Робот в спячке (пропускает раунд) |
| Rebooting | Робот перезагружается после смерти |
| Destroyed | Робот уничтожен (потерял все LifeTokens) |

### Система HP и LifeTokens

В оригинальных правилах RoboRally используются две системы:
- **Damage (HP)** - жетоны повреждения (0-9): влияют на количество карт и блокировку регистров
- **LifeTokens** - дополнительные жизни (3 максимум): тратятся при уничтожении робота

**Логика:**
- При 10+ уроне робот переходит в состояние Rebooting
- Если есть LifeTokens - тратится 1 LifeToken, робот воскресает
- Если LifeTokens = 0 - робот уничтожается (Destroyed)

### Механика повреждений

```
TakeDamage(amount):
    Damage += amount
    if Damage >= 10:
        if LifeTokens > 0:
            LifeTokens--
            Status = Rebooting
            Damage = 0
        else:
            Status = Destroyed
```

### Блокировка регистров

#### Почему регистры блокируются?

Когда робот получает повреждения, его память повреждается. Чем больше повреждений, тем сложнее роботу запоминать программу. При 5+ повреждениях регистры начинают "заклинивать" (lock).

#### Когда начинают блокироваться?

Блокировка начинается при **5 повреждениях**:
- 5 HP → заклинивает регистр 5
- 6 HP → заклинивают регистры 4-5
- 7 HP → заклинивают регистры 3-5
- 8 HP → заклинивают регистры 2-5
- 9 HP → заклинивают все регистры 1-5

#### Как работают заблокированные регистры?

1. **Заклинивший регистр остаётся с той же картой** - робот выполняет её каждый раунд
2. **Ремонт происходит в обратном порядке** - сначала разблокируется регистр 1, потом 2 и т.д.
3. **При воскрешении регистры НЕ разблокируются** - повреждения сохраняются
4. **При PowerDown** - повреждения сбрасываются, регистры разблокируются

#### Раздача карт и блокировка

| HP | Карт в руке | Заблокировано |
|----|-------------|---------------|
| 0 | 9 | 0 |
| 1 | 8 | 0 |
| 2 | 7 | 0 |
| 3 | 6 | 0 |
| 4 | 5 | 0 |
| 5 | 4 | 1 (регистр 5) |
| 6 | 3 | 2 (регистры 4-5) |
| 7 | 2 | 3 (регистры 3-5) |
| 8 | 1 | 4 (регистры 2-5) |
| 9 | 0 | 5 (все регистры заблокированы) |

### Воскрешение (Reboot)

- Воскресший робот получает +2 повреждения
- Чекпоинты сбрасываются

### Power Down

- Робот может войти в режим PowerDown
- Пропускает все регистры
- Восстанавливает все повреждения в начале следующего раунда

### Уничтожение робота

Робот уничтожается если:
- Получает 10-й жетон повреждения (при 0 LifeTokens)
- Падает в яму
- Выталкивается за пределы игрового поля

При уничтожении:
- Теряет 1 LifeToken
- Воскресает на контрольной точке в начале следующего раунда
- Получает +2 повреждения

## Лазерная система

### Типы лазеров

| Источник | Урон | Описание |
|----------|------|----------|
| Лазер на плитке | 1 HP | Стреляет каждый регистр |
| Робот-лазер | 1 HP | Стреляет в направлении робота |
| Double Barrel Laser | 1 HP | Стреляет вперёд, влево, вправо |
| Rear Laser | 1 HP | Стреляет назад |

### Приоритет лазеров

Лазеры стреляют по приоритету:
1. **ByPosition** - от левого верхнего угла
2. **ByDirection** - по направлению
3. **None** - без приоритета

### Алгоритм стрельбы

```
PrepareShots():
    Для каждого робота:
        1. Проверить лазер на плитке
        2. Применить стратегию робота (LaserStrategy)
        3. Создать список направлений стрельбы

Fire():
    1. Отсортировать выстрелы по приоритету
    2. Для каждого выстрела:
        a. Вычислить траекторию (Path)
        b. Найти первого робота на траектории
        c. Нанести урон
```

### Путь лазера

```
CalculatePath(start, direction):
    pos = start.Move(direction)
    while pos в пределах карты:
        if стена: остановиться
        добавить pos в path
        pos = pos.Move(direction)
    return path
```

## Апгрейды (Upgrades)

### Доступные апгрейды

| Апгрейд | Тип | Описание |
|---------|-----|---------|
| Double Barrel Laser | Permanent | Стреляет в 3 направлениях (вперёд, влево, вправо) |
| Rear Laser | Permanent | Стреляет назад |
| Hover Unit | Permanent | Игнорирует конвейеры и ямы |
| Power Slide | Permanent | +1 дополнительное движение за ход |
| Drifting | Permanent | (в разработке) |
| Spiky | Permanent | Наносит 1 урон при столкновении |
| Deflector Shield | Permanent | Блокирует 1 урон от лазера |
| Brakes | Permanent | Останавливается перед стеной/роботом |
| Boink | Temporary | Отталкивает атакующего на 2 клетки |
| Overclocked | Temporary | Повторяет последний регистр |

### Типы апгрейдов

- **Permanent (Постоянный)** - остаётся навсегда
- **Temporary (Временный)** - действует 1 раунд

### Архитектура Strategy Pattern

Апгрейды используют паттерн "Стратегия" для модульности:

```csharp
// Базовый класс
public abstract class UpgradeEffect
{
    IMovementStrategy? GetMovementStrategy();
    ILaserStrategy? GetLaserStrategy();
    IDamageStrategy? GetDamageStrategy();
    IConveyorStrategy? GetConveyorStrategy();
    ICardExecutionStrategy? GetCardExecutionStrategy();
}
```

### Интерфейсы стратегий

| Интерфейс | Описание |
|-----------|---------|
| `IMovementStrategy` | Управление движением |
| `ILaserStrategy` | Стрельба лазером |
| `IDamageStrategy` | Обработка повреждений |
| `IConveyorStrategy` | Взаимодействие с конвейерами |
| `ICardExecutionStrategy` | Выполнение карт |

### Фазы срабатывания (TriggerPhase)

| Фаза | Описание |
|-------|----------|
| BeforeCard | Перед выполнением карты |
| AfterCard | После выполнения карты |
| BeforeMovement | Перед движением |
| AfterMovement | После движения |
| BeforeLaser | Перед лазером |
| AfterLaser | После лазера |
| OnDamage | При получении урона |
| OnHit | При попадании |
| OnMove | При перемещении |

## Важные особенности

### Godot csproj

```xml
<Project Sdk="Godot.NET.Sdk/4.6.1">
  <PropertyGroup>
    <TargetFramework>net8.0</TargetFramework>
  </PropertyGroup>
  <ItemGroup>
    <ProjectReference Include="../AiTest.Core.csproj" />
  </ItemGroup>
</Project>
```

**Важно:** 
- Использовать `Godot.NET.Sdk` а не стандартный Microsoft.NET.Sdk
- Не добавлять PackageReference на GodotSharp - он идёт с SDK
- После перемещения проекта удалить папки `obj` и `.godot`

### Целевая версия .NET

AiTest.Core и Godot проекты должны использовать **net8.0** (не net10.0) для совместимости с Godot Mono.

### Ошибки LSP в IDE

Красные подчёркивания в IDE - это нормально. Godot.NET.Sdk не понимается стандартными IDE. Сборка при этом работает.
